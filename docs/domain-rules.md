# 领域边界

协调高标仓箱货批次、班列窗口、设备计量和绿色费用分摊。

现有领域资料围绕以下边界组织：

- 箱货批次谱系
- 仓位与班列窗口
- 设备计量版本
- 跨租户能耗分摊
- 结算复核与恢复

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 已落地的服务规则（v2）

`src/hub/` 是上述边界的可执行实现，关键规则与 `fixtures/context.json` 的约束一一对应：

- **谱系不可覆写**：批次只按现存数量记账；拆分、合并、改配、破损、温区降级都新建父子批次，
  子批次只继承异常发生节点之前已完成的确认，异常只阻断未完成链路。
- **逐段确认**：到场→卸货→质检→上架→交铁路严格按序，节点回执幂等；
  上架前校验库位温区，交铁路前校验班列窗口与截关时间。
- **计量版本**：读数按抄表时点形成只增版本；补抄插入历史位置并重排版本号。
  相同回执编号同值幂等返回原读数；同编号不同值/时点进入隔离区，复核人员才可采纳或作废。
- **缺口与停机**：停机登记抄表缺口；区间存在未补齐缺口时禁止分摊，
  同仪表同区间禁止重复分摊——双重防线防止“同一批货被两次计量”。
- **跨租户分摊**：私表归表主；公共表按区间内温区占用箱量比例分摊；
  碳排使用版本化因子，因子来源、版本随分摊留痕。
- **权限分离**：企业视图只返回本方订单/货物/分摊行；抄表录入人与争议提出人
  均不能审批争议减免；分摊经独立复核才可结算。
- **恢复与溯源**：仓储可整体快照/恢复；`recover` 幂等重建抄表缺口、截关、
  结算复核三类告警；`trace_allocation` 从一笔分摊还原读数版本、碳排依据、
  货物批次谱系、异常去向与审批记录。
